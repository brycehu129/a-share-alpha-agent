# 后续计划（ROADMAP）

按"为什么要做 / 触发条件 / 现状"记录，**没做的就明说没做**。排序不代表承诺时间。

## 已确认要做

### 1. 备用实时行情源
- **为什么**：盘中信号、条件入场、止损全部依赖腾讯行情（免费、非官方）。接口一变、被限流或 IP 被封，盘中就整体失明——引擎会因"报价不新鲜"什么都不做，健康检查会报警，但**当天的机会/风险已经错过**。
- **做法草案**：`live_quote` 抽象成多个 provider（腾讯为主，再接 1–2 个：新浪 `hq.sinajs.cn`、东方财富 `push2`，或有 token 的付费源如 iTick/必盈）；主源失败或结果与备源偏离超阈值时切换；**每次切换记录并告警**；备源同样要过新鲜度/时区/单位校验（科创板成交量单位就是个真实的坑）。
- **验收**：模拟主源挂掉，引擎在 1–2 轮内自动切到备源；两源对同一只票的价差监控可见；切换事件写入操作记录/健康面板。
- **现状**：未开始。

### 2. 近实时消息面
- **为什么**：目前只核查公告（东方财富），标题关键词很粗；传闻、研报、行业消息、盘前集合竞价信息都没有。
- **做法草案**：接入财联社电报等；只做**风险过滤 + 标注**，不让 AI 从消息里"预测涨跌"；分类结果同样要回测"它拦下的票后来怎样"，否则无法判断是否错杀。
- **现状**：未开始（第一版夜间公告核查已上线）。

## 等前瞻数据再决定

### 3. 反转类候选（研究，不交易）
- **为什么**：本地 35 日回放里，最弱 10% 行业的随机抽样屏障净收益最好、强势行业最差（反转行情）。如果前瞻基线（`weak_industry`/`mid_industry`）也这样，说明"强势行业内找动量"这个前提要重新考虑。
- **触发条件**：前瞻基线累计 ≥15 个日期组且方向一致。
- **做法草案**：先作为**只留档、不成交**的第三条 track 并行收集证据，走同一套基线/证据体系；证据够了才考虑成交。
- **现状**：只有基线对照在收集，没有新 track。

### 4. 选股层参数的"提议 → 确认"通道
- 行业权重、过热系数、市场分暂停线，以及突破/回调的阈值（近 3 日涨幅、量比、MA5 偏离…）。生效要**同步 bump `selection_version`**（否则新旧参数样本混池），代码里好几处用固定常量分池，要改成动态。
- **现状**：`review_pipeline` 只出建议、从不自动生效；通道没接。

### 5. AI 读复盘、生成参数提议
- 没有已验收样本时它只会编故事。触发条件：前瞻样本达到提议门槛（n≥30、日期组≥15）。**建议先加"批准冷却期"**：批准一条后必须积累够新版本样本，才能批准下一条，防止拿噪声反复调参。

### 6. 合约模拟 vs 真实成交对比
- 日线推演与盘中引擎真实成交差多少（决定日线证据可信度）。需要两边各有几周数据。

### 7. 判断口径（提示词）版本化
- AI 提示词的变更也走"提议 → 确认"，并记录版本。

## 工程
- **08:40 盘前流程耗时实测**：必须在 09:20 前跑完，否则当天没有计划。服务器上看：`journalctl -u alpha-shadow-daily.service --since "3 days ago" | grep -E "Starting|Finished|Deactivated"`。如果太慢，把选股/冻结拆成独立的轻量任务并提前触发。
- **异地备份自动化**：目前靠手动下载。自动化需要一个你自己的、不进公开仓库的存储凭据。
- **入场规则再优化**：计划当天没触发就放弃（不补买）。是否允许"隔天延续"（需要隔夜公告复核）要看证据三层里的触发率和"差一点"记录。
- **组合层面的只提示**：集中度、行业暴露、总仓位（只提示，不替你决策）。
