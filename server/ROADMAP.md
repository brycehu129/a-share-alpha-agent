# 后续计划（ROADMAP）

按"为什么要做 / 触发条件 / 现状"记录，**没做的就明说没做**。排序不代表承诺时间。

## 已确认要做

### 1. 备用实时行情源
- **为什么**：盘中信号、条件入场、止损全部依赖腾讯行情（免费、非官方）。接口一变、被限流或 IP 被封，盘中就整体失明——引擎会因"报价不新鲜"什么都不做，健康检查会报警，但**当天的机会/风险已经错过**。
- **做法草案**：`live_quote` 抽象成多个 provider（腾讯为主，再接 1–2 个：新浪 `hq.sinajs.cn`、东方财富 `push2`，或有 token 的付费源如 iTick/必盈）；主源失败或结果与备源偏离超阈值时切换；**每次切换记录并告警**；备源同样要过新鲜度/时区/单位校验（科创板成交量单位就是个真实的坑）。
- **验收**：模拟主源挂掉，引擎在 1–2 轮内自动切到备源；两源对同一只票的价差监控可见；切换事件写入操作记录/健康面板。
- **现状**：未开始。

### 2. 近实时消息面
- **为什么**：目前只核查公告（东方财富），标题关键词很粗；传闻、研报、行业消息、盘前集合竞价信息都没有。
- **做法草案**：接入财联社电报等；只做**风险过滤 + 标注**，不让 AI 从消息里"预测涨跌"；分类结果同样要回测"它拦下的票后来怎样"，否则无法判断是否错杀。
- **现状**：未开始（第一版夜间公告核查已上线）。

- **触发条件**：前瞻基线累计 ≥15 个日期组且方向一致。
- **做法草案**：先作为**只留档、不成交**的第三条 track 并行收集证据，走同一套基线/证据体系；证据够了才考虑成交。

### 8. 提议页可编辑（用户手动提议）— 待讨论
- **现状**：提议页只有审批、没有创建。`proposals.submit()` 除测试外没有任何调用方；AI 提议者是第 5 项，没做；且样本门槛（n≥30、日期组≥15，须来自当前执行版本）要 exec-0.3 冻结计划（2026-09-21 起）后 3–4 周才可能满足（含国庆更久）。
- **草案**：`proposals.submit_user()` + `POST /api/proposals/create` + 每个参数一个编辑按钮。仍受范围 / 单次步长 / 风控红线约束、仍要你批准、仍从下一个 08:40 冻结起生效；只对手动提议免样本门槛，并标注"用户直接提议"；AI 路径不得借用这个豁免（`submit()` 拒收 `source='user'`）。`spec_rows` 需补 `track_key / parameter / 原始值 / floor / ceiling / step_cap`。
- **要一起想清楚**：每次批准都会 bump 修订号、执行版本变 `exec-0.3.rN`、**样本重新计数**，并让其它待确认提议全部作废——频繁手动改会不断清零证据池；多参数需逐个批准。
- **顺带**：`proposals.py`、`sentinel.py` 顶部无条件 `import fcntl`，Windows 本地无法直接 import（引擎已做过兼容，这两个没有），本地测试要伪造 `fcntl`。

### 11. 节点事件疑似被"每轮 5 条"上限挤掉 — 待核实（未证实）
- **疑点**：`intraday_engine.MAX_EVENTS_PER_TICK=5`（`apply_signals`）；边沿信号被挤掉会顺延，但 09:45 / 13:05 / 14:30 的节点信号只在跨过节点的那一轮存在（`node_due`），被挤掉后没有顺延，该股该节点的情景研判就丢了。页头"情景只有 32 条"可能与此有关。
- **核实**：在服务器上看 `intraday/events-<日期>.jsonl` 与 `sentinel/done/*.json`，统计节点事件被挤掉的次数；确认后再决定是把节点信号改成可顺延，还是把节点事件排除出 5 条上限。

### 12. 资金流上线后的观察项 — 待观察
