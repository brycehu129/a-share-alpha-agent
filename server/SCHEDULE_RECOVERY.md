# GitHub 调度补偿

保留 GitHub Actions 与现有网页。原定时点之外，每个交易周工作日北京时间08:17至20:17增加每小时补查。补查同样可能延迟，不提供准点执行保证。

日报根据实际开始时间选择阶段：07:10起补数，08:40起盘前，15:35起收盘初稿，18:20起收盘终稿。延迟的补数事件会升级为当前应执行的报告，不再固定跳过策略计算。凌晨及23点后不补造上一日盘前报告。

每阶段完成状态保存在 operations.json 的 checkpoints 中，成功或确认休市的阶段不重复运行；失败、数据不全会在后续补查重试。09:35后独立进行一次报告与过期计划核对，确保早盘报告成功但开盘观察漏跑时，也能记录未成交原因。所有任务继续使用同一个 market-report-history 并发组保护账本。

盘前延迟报告明确标记实际生成时间，不把开盘后信息当成盘前预测。预测仍按实际冻结时间决定最早可执行日。已经错过首个允许入场窗口的旧计划只追加 skipped 记录，不修改原预测、不改变持仓和现金。

开盘观察增加09:33备用尝试和09:47审计触发；仍只允许09:30至09:35的有效实时报价成交。已尝试过的计划不重复处理，09:47不补造成交。因 GitHub 排队和数据源时效，仍可能整日没有模拟成交。

这次改动不接入 ChatGPT 独立日报，也不改变股票评分、仓位规则或真实交易权限。网页通过原有状态与交易记录接口显示补偿结果。
